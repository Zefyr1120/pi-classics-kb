# 古籍数据工程：脚本清单与处理思路沉淀

> 用途：本文档记录古籍数据清洗流水线中全部脚本的功能、遇到的问题、解决思路与结果，既是操作手册，也是**项目经历素材**（Agent 工程 / 数据工程方向）。
> 建立日期：2026-09-10｜最后更新：2026-09-10
> 范围：`古籍/tools/` 全部脚本 + 相关的 `guwen-cleaning` 技能
> 配套：`tools/README.md`（现行工具速查）、`tools/_已归档-一次性脚本/`（已退役脚本）

## 一、这条流水线在解决什么问题

**目标**：把从互联网抓取的古籍原文（HTML 噪音多、无标点、繁体、错字、注家混排），加工成**便于 Agent 检索、理解和引用的结构化文本**。最终服务的是八字性格分析产品——Agent 要在分析时准确引用古籍原文，所以底本必须干净、可定位、分层清晰。

**核心约束**（贯穿全部脚本）：
1. **精确不失原意**——不增删、不改写义理，断句/翻译/解释均以原文为据；
2. **可校验**——每一步改动都可回溯（git 基准 + 逐字校验）；
3. **渐进式披露**——上层只放导航摘要，细节留在下层，Agent 按需下钻。

**工程挑战的四个层次**：

| 层次 | 问题 | 对应脚本 |
|---|---|---|
| 采集 | 网页噪音、超长单页截断、源不可用 | fetch_*.py / .ps1 |
| 结构化 | 一份大文件怎么切成 Agent 可检索的单元 | split_guji.py / parse_zhouyi.py / split_sanming_vols.py |
| 内容净化 | 无标点、繁体、BOM、装饰符、注家混排 | convert_simplify.py / screen_guji.py / 素问断句系列 / split_ziping_chapters.ps1 |
| 质量保证 | 改了 5 万字，怎么确认没改错一个字 | suwen_verify_punct.py / scan_variants.py |

## 二、现行工具（保留在 `tools/`）

### 2.1 采集层

#### `fetch_mirror.ps1` — 镜像站全文抓取
- **做什么**：从殆知阁（daizhige.org）等镜像站抓取术数类古籍全文。
- **问题**：原始站点的自定义 MCP 采集通道不可用。
- **思路**：放弃 MCP，实测出"殆知阁＝术数备选主源"，用 PowerShell + WebRequest 直抓，落盘前统一转 UTF-8。
- **结果**：渊海子平（179KB/2555 行）等书全文落盘，成为 B 组采集成败关键。

#### `fetch_guoxue3000.ps1` / `fetch_daizhige.ps1` — 分源抓取
- **做什么**：分别对接国学3000 与殆知阁两个源。
- **问题**：单源覆盖不全；且**超长单页经 open_page 会截断**。
- **思路**：按书号定点抓取（国学3000 书号：滴天髓378/渊海子平374/神峰通考428/三命通会330/内经272）；长书换源或分章抓。
- **结果**：形成"国学3000 主源 + 殆知阁备选"的双源策略。

#### `fetch_web_text.ps1` — 通用网页正文提取
- **做什么**：从普通网页提取正文文本。
- **结果**：三命通会卷七补遗三篇（子平说辩/论贫贱凶恶/论寿夭，通行本缺、四库本有）据此从中华文库补入。

#### `fetch_clean_sources.py` — 清洗源抓取
- **做什么**：抓取已清洗的整理本作为校勘参照。

#### `fetch_sanming_vols.py` + `sanming_vols.json` — 三命通会分卷抓取
- **做什么**：按卷抓取三命通会。
- **问题**：三命通会 12 卷，逐卷手工抓取易错漏；且**殆知阁旧源有 1606 处"防"字系统性损坏**（OCR/编码问题）。
- **思路**：把卷号与 URL 配置外置为 `sanming_vols.json`，脚本读配置循环抓；发现旧源损坏后**整体换源**为国学3000 重采。
- **结果**：12 卷 383 章干净落盘，无"防"字损坏。

#### `fetch_sanming_juan7_supp.py` — 卷七补遗
- **做什么**：补入四库本独有的卷七三篇。
- **问题**：通行本缺这三篇，但**它们是整段无标点**，且不在文件级扫描告警里。
- **思路**：定点抓取 + 单独登记到"已知无标点清单"，提醒后续按段落粒度复核。
- **结果**：卷七补齐为 25 章。

### 2.2 结构化层

#### `split_guji.py` — 通用古籍拆分（**主力工具**，18KB）
- **做什么**：把一份全文大文件按卷/篇/章/节/日拆成多个 `NN-标题.md`，并生成索引。
- **覆盖**：素问81篇、灵枢、难经、五行精纪32卷、神峰通考59节、穷通宝鉴10干、命理约言59节、滴天髓辑要39论、六壬说约/六壬大全/壬归、御定六壬直指60日等 **14+ 部书**。
- **问题 1**：各书章节边界标志各不相同（标题行、"第一/一者"、空行、"卷X"）。
- **思路**：不写死单一规则，改为**按书配置正则 + 统一输出格式**；拆不出结构时回退人工分片。
- **问题 2（典型 bug）**：御定六壬直指用 `[甲-癸]` 字符区间匹配天干，但 **Unicode 里"甲"到"癸"之间还夹着别的汉字**，导致误匹配。
- **思路**：改为显式枚举 10 个天干，修复后 60 日 × 12 局 = 720 局全部正确。
- **问题 3**：底本（`*-全文.md`）与拆分目录（同名文件夹）并存时，粗筛会误报底本"装饰符残留"。
- **思路**：给脚本加"底本豁免"——有同名拆分目录时，底本保留原始标记不再报错。
- **结果**：全库完成结构化，各领域 README + 古籍总索引建立。

#### `parse_zhouyi.py` — 周易专项解析（15KB）
- **做什么**：按卦拆 64 文件 + 十翼 5 篇 + 索引。
- **问题**：卦辞/彖/大象/爻辞/小象/文言**多层嵌套**，普通按标题切分切不开。
- **思路**：专项解析器，按每卦结构解析出层，再**表格化输出**（层｜内容），使每卦可逐层定位。
- **结果**：64 卦 + 十翼全部结构化，层与层不混。

#### `split_sanming_vols.py` — 三命通会按卷拆分
- **结果**：383 章落盘，`目录.md` 按项目路径编排。

#### `split_ziping_chapters.ps1` — 子平真诠按章拆分（**已废弃**）
- **做什么**：原把子平真诠评注全文按章拆 44 文件。
- **问题（根因）**：底本本身就是**沈孝瞻原文 + 徐乐吾评注混排**，机械按"徐注："切分只能分块、**无法判断哪段是真原文**，导致部分徐注被误标为【原文】。
- **处置**：2026-09-10 标注 ⚠️已废弃，改为"权威底本重录 + 逐章重建"（见 3.1）。
- **教训**：**机械规则解决不了语义问题**。当噪声与信号用同样格式混排时，必须引入权威外部基准做对照，而不是在脏数据里做正则。

#### `split_ditianzhui_layers.ps1` — 滴天髓分层拆分（**已废弃**）
- **问题（根因）**：只删【任氏曰】标记块，但任注的**案例命造和议论段落不带标记**，机械删除后仍残留 66 例命造。
- **处置**：2026-09-10 标注 ⚠️已废弃，改为状态机逐章剥离（见 3.2）。
- **教训**：**"标记"不等于"边界"**。清理前要先确认噪声的完整形态，而不是只认它最显眼的那个标记。

### 2.3 内容净化层

#### `convert_simplify.py` — 繁简转换
- **做什么**：全库繁体→简体（OpenCC t2s），105/225 文件。
- **问题（关键）**：无脑转换会**误伤必需保留的字**——乾坤/乾卦/乾造（"乾"）、宫商角徵羽（"徵"）。
- **思路**：转换后做**保护字回填**，把这些术语字还原。
- **结果**：全库简体统一，术语零误伤；同时清理 BOM。

#### `screen_guji.py` — 全库质量粗筛（6KB）
- **做什么**：一次扫描输出 7 类问题清单——标点不足、装饰符残留、标题书名号、标题全角空格、BOM、繁体残留、未拆分全文。
- **问题（认知升级）**：一开始把它当"质检标准"，但它**只是粗筛**——文件级标点密度正常 ≠ 卷内没有无标点段落（三命通会卷七就漏报了）。
- **思路**：明确定位为"定位工具"而非"验收工具"；配套要求在**章节/段落粒度复核**，并把已知无标点清单登记进专项指南。
- **结果**：成为每本书清洗前后的标准动作（先跑它观察格式、清洗后跑它验收）。

#### 素问断句系列（`suwen_punct_pian*.py`，**78 个脚本，已退役**）
- **做什么**：素问王冰注本**逐篇**断句，覆盖篇 1-71、74-81。
- **问题**：整本素问几十万字**整段无标点**（原始标点密度 0.026-0.05），需逐字断句；且王冰注本里**正文与注文逐句夹注**（【】包裹），断句时不能把注文当正文。
- **思路（关键设计）**：每个脚本是一个 `REPL = {行号: 新内容}` 字典——
  - **按行号精确替换**，不碰其他行，杜绝误伤；
  - 行号+内容双锚定，脚本本身即是**可复核的改动记录**；
  - 保留异体字（如 PUA 区 U+EF2E）、保留"新校正云"分隔符；
  - 每篇完成即 `suwen_verify_punct.py` 逐字校验 + git 提交。
- **结果**：素问王冰注本全书断句完成（标点密度 0.037→0.218 等），**逐字核对无增删**；每个脚本对应一次 git 提交，形成完整的可追溯链。
- **为什么退役**：一次性产物——每篇只用一次，且内容已固化进古籍文件本身。**留档不留用**。

#### `suwen_punct_fix_variants.py` — 异体字修正
- **做什么**：统一处理断句过程中发现的异体字问题。

#### `suwen_verify_punct.py` — 断句内容完整性校验（**核心方法论**，3KB）
- **做什么**：以 git 某版本为基准，校验当前文件**内容是否逐字一致**。
- **问题（最核心的难点）**：断句会改动大量行（加标点），怎么证明"只加了标点、没改字"？
- **思路（精妙处）**：**先把两侧的标点全部剥离，再逐字比对**——
  - 剥离字符集：`，。；：？！、"“”《》` + ASCII 直引号；
  - 剥离后必须**逐字完全一致**（不增删、不改序、不改字）；
  - 引号风格差异（直/弯）因被剥离而不会误报；
  - 全角空格 U+3000 单独统计为"格式差异"，不算实质差异。
- **结果**：素问全篇断句的**零错字保证**；此法后被推广为通用校验范式。
- **可提炼的通用思想**：**"归一化后再比对"**——要验证"A 只是 B 加了些附加物"，就把附加物从两边都去掉，再比剩下的。这个思路适用于任何"增量式修改"的校验场景。

#### `verify_qiongtong_entries.py` — 结构序列比对 ＋ 另采源一致性（已归档）
- **做什么**：验证《穷通宝鉴》「全文 ↔ 条目级结构」非空行序列完全一致；2026-09-15 起兼容**另采源条目**。
- **问题 1**：注解层（【章旨】【疏解】）是后加的，不能进入比对。
  - **思路**：以「首个 `## ` 及其后一律跳过」为界，只比正文层。
- **问题 2（关键）**：补校引入的**另采源内容不在底本全文内**，若一并比对，会误报“丢失/错位”。
  - **思路**：分两类标记——整条另采源（文件头标「另采源条目」）→ **整文件排除**出序列比对；部分另采源（如 `## 另采源命例` 小节）→ 因首个 `##` 就跳过而自然排除。
  - **补充**：被排除的内容不能“没人管”——另做**与对照本原文层逐行命中**校验（空白归一化后 substring），防止手工转录走样。
- **结果**：底本序列 **1143 行仍全等**；另采源 2 文件 / 31 行全中。
- **可提炼的通用思想**：「**排除 + 单列校验**」：当新引入的内容不属原基准时，不能默默跳过，而要给它建第二条基准。

#### `scan_variants.py` — 异体字扫描
- **做什么**：扫描全文，找出可能的异体字/PUA 字符，供人工判断是否保留。

#### `build_suwen_buyi.py` — 素问补遗构建
- **做什么**：从四库全书本补入素问篇 75-81（正文+王冰注+新校正）。
- **问题**：通行本缺这 7 篇；四库本有，但**异体字多、且"乾/徵"需保护**。
- **思路**：抓取后做异体归一 + 保护字回填（沿用 convert_simplify 的保护清单）。
- **结果**：补遗 7 篇落盘，素问完璧。

### 2.4 `.pi/` 与技能层（非 tools，但属流水线）

- `古籍/guwen-cleaning/`：把上述流程固化为可复用技能（SKILL.md + 清洗核心规则 + 格式规范 + 各书专项指南）。**这是"脚本 → 方法论"的沉淀层**。
- `skill/`（八字分析技能）：产品核心内容层，与古籍层解耦。
- `.pi/agents/`（流派子代理提示词）：`ditianshui`／`zipingzhenquan`／`qiongtongbaojian`／`report-writer`；均 `isolate: true`。
- `.pi/extensions/guji-tools/`（2026-09-15 新增）：**按节取用工具 `get_section`**。解决"MD 文件内部只能按行切片"造成的截断（实测：212 个带注解的文件中 32 个（15%）的注解内容位于第 40 行之后，最坏丢 15 行）——按 `## 标题` 锚点返回单节，并附**层标注**（原文层／项目自撰注解层／注家层），从工具层杜绝"注解被当原文引用"。MD 源零改动。
- `.pi/extensions/subagent/`：子代理调度器。2026-09-15 改造：工具白名单里的"扩展工具"在 isolate 子进程里用 `-e` 显式加载（**关键事实**：`--no-extensions` 只关扩展"发现"，不阻止 `-e` 指定的扩展——pi 源码里是 `noExtensions ? cliEnabledExtensions : merge(...)`；不掌握这一点，自定义工具在隔离子代理里根本无法生效）。

> **沉淀（可迁移到其他项目）**：给子代理加自定义工具时，光改白名单不够——要确认加载路径。否则工具名在提示词里、实际未注册，模型会编造或报错，而这在"多轮分析"里很难被发现。

## 三、2026-09-10 新增：两大"分层净化"工程

这两件事不属于旧脚本系列，但是本项目**最能体现 Agent 工程能力**的部分——都是"发现脏数据 → 溯源 → 换权威基准 → 重建 → 校验"的完整闭环。

### 3.1 子平真诠：剥离徐乐吾评注层（47 章重建）

**问题诊断**（三步溯源）：
1. 原库 44 章，缺 34/37/41/46 四章；
2. 第 08 章"取用五法（扶抑/病药/调候/专旺/通关）"**被标为【原文】，实为徐乐吾评注**——证据是文中引伍朝枢、蔡元培、朱家骅、谭延闿、王克敏等**民国人物**，而沈孝瞻是清乾隆人；
3. 第 24 章混入**网络乱入文本**（"…金字塔顶笑看风云！不畏一切的战心！"）。

**根因**：底本本身就是沈氏原文 + 徐注 + 林注混排，机械切分无法区分层。

**解决思路**（换基准，不在脏数据里修）：
1. 找权威公版底本（易德轩 47 章全文），**重录纯原文**落为基准文件；
2. 用基准文件**重建全部 47 章**，正文一律回归沈氏原文；
3. **自撰【疏解】**替代被移除的注释——体例：章旨（本章论什么）/ 疏解（概念与论证脉络），只疏解原文、不列命例；
   （**2026-09-10 二次净化**：原体例还含第三段"项目用法"（落到"八字→心理"的取值口径），已全库删除，知识库回归纯知识库定位，不再夹带项目应用口径。）
4. 补全 4 缺章；删除第 48 章（全章为徐氏附论，含其自著《滴天髓征义》引用）；
5. 全量备份 + 更新所有交叉引用（索引/README/采集进度/书目规范）。

**结果**：47 章编号连续无缺，正文零徐注/林注残留，每章附项目自撰疏解（约 400-1100 字/章）。
**关键验证**：第 08 章纯原文止于"非用而即用神也"（520 字），**证实"五种取用法"确非沈氏原文**——为"推翻格局=人生重心假设"提供了原典级实证。

### 3.2 滴天髓：剥离任铁樵批注层（64 章）

**问题**：任注与项目口径存在**已知立场冲突**（阴阳同生同死 vs 十干长生/火土同宫、废神煞、批"财为父"），必须整体剥离。

**解决思路（状态机剥离）**：
- 逐章扫描，遇 `任氏[曰日]` 进入"丢弃模式"，遇 `【原注】/【原文】/# 标题` 退出——解决"标记不等于边界"问题；
- 剥离 3921 行任注+案例；校验正文残留=0；
- 发现旧"清洁版"全本文档**声称残留=0 但实有 66 例命造**（机械移除不彻底），遂**按 64 章重建成新全本**。

**结果**：64 章分层本 + 重建全本（554 行/137 原注/64 章），正文层干净。

### 3.3 可提炼的通用工作流（★ 项目经历核心）

```
① 现象发现 → ② 抽样精读定位脏数据类型
           → ③ 溯源根因（是底本问题还是脚本问题？）
           → ④ 找权威外部基准（不在脏数据里修）
           → ⑤ 全量备份（可回滚）
           → ⑥ 重建 → ⑦ 校验（残留归零）→ ⑧ 更新交叉引用
```

**两条重要教训**：
- **机械规则解决不了语义问题**：噪声与信号同格式混排时，正则无能为力，必须引入外部权威基准。
- **"标记"不等于"边界"**：清理前先确认噪声的完整形态，只删标记会残留大片。

## 四、从 git 记录提炼的处理思路（可迁移到新岗位）

> 本项目 188 次提交中有大量可迁移的工程模式。以下按主题归纳。

### 4.1 增量式修改的可验证性（最强的一条）

**做法**：素问断句的每次改动都写成 `{行号: 新内容}` 脚本 → 执行 → `suwen_verify_punct.py` 逐字校验 → git 提交。
**思想**：**把"改动"本身变成可审计的产物**。脚本即 diff，校验即测试，提交即版本。
**可迁移到**：任何大规模文本/配置/数据的批量修改（如代码迁移、配置升级、数据订正）——写"声明式改动 + 自动校验"，而不是手工编辑。

### 4.2 归一化比对法

**做法**：校验前先把标点/空格等"无意义差异"从两侧剥离，再逐字比对。
**思想**：**先消除可比性噪音，再做严格比对**。
**可迁移到**：代码格式化后的语义等价检查、文档重构的完整性验证、数据清洗结果校验。

### 4.3 分层与渐进式披露（技能文档的组织哲学）

**做法**：目录只放摘要 → 卷级文件头部放"本卷概览" → 细节留章节层。SKILL.md 只放流程骨架，细节在 references/ 按需加载。
**思想**：**信息分层，按需下钻**——与 Claude Skill / Pi Skill 的渐进式披露机制同构。
**可迁移到**：技术文档、Prompt 工程、知识库设计。

### 4.4 换基准优于修脏数据

**做法**：发现底本混排后，不停留在"用正则挑出干净部分"，而是另找权威版本重录。
**思想**：**脏数据里做正则的边际成本会失控；有干净基准时直接换。**
**可迁移到**：数据源治理、遗产代码迁移。

### 4.5 底本与成品分离

**做法**：`*-全文.md`（原始底本，保留所有原始标记）与拆分目录（清洗成品）并存；脚本对底本豁免质检。
**思想**：**保留原始底本 = 永远可回溯、可重新加工**。
**可迁移到**：原始数据留存策略、ETL 的 raw/clean 分层。

### 4.6 发现即登记（认知的显式化）

**做法**：`screen_guji.py` 只是粗筛、卷七无标点段落会漏报——这个"工具的局限"被**写进技能规则**，而不只是记在脑子里。
**思想**：**把"已知局限"文档化，防止后续误用。**
**可迁移到**：工具文档、on-call 手册、测试用例的已知盲区标注。

### 4.7 保护清单法

**做法**：繁简转换前先列出"不可转换词"（乾坤/乾造/宫商角徵羽），转换后回填。
**思想**：**批量操作前先识别例外，用白名单兜底。**
**可迁移到**：批量重命名、代码重构、正则替换、i18n。
