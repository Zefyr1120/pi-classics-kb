# 古籍知识库检索评测（三书）

> 目的：在**同一批 query、同一批 gold、同一个嵌入模型**下，比较「本项目结构法」与「传统 QAG」的章节级召回率。
> 语料：《子平真诠》47 章 ＋《滴天髓》64 章 ＋《穷通宝鉴》148 节 ＝ **259 个评测单元**。
> 状态：进行中（见文末进度）。

---

## 一、红线（数据隔离纪律，不可违反）

| # | 纪律 | 检查方式 |
|---|---|---|
| R1 | **QAG 臂的索引只允许来自「原文层」**：`## 原文` ＋ 底本自带古注（滴天髓 `## 原注` 刘基）。**章旨／疏解／检索词／关联章节／何时调用等一切项目自撰加工层，一个字都不进 QAG 的库。** | `build_qag_index.py` 只读 `section["orig"]` / `section["note"]`；建库时断言 chunk 文本不含注解层标记；`verify_isolation.py` 交叉扫描 |
| R2 | **结构法臂才允许使用注解层**（章旨／检索词／疏解）——这些正是被评测的"处理方法"本身 | 同上，反向断言 |
| R3 | **query 生成器只见原文**（＋原注），不得见标题／章旨／疏解／检索词 | `gen_queries.py` 的 prompt 只插 `orig`+`note` |
| R4 | gold＝该 query 生成时所依的节；两臂共用同一 gold 文件，不得各标各的 | `queries.jsonl` 单一来源 |

> 为什么 R1 是命门：章旨/疏解是项目投入最大的加工产物。若把它喂进 QAG，等于把答案放进被比较的库——数字会好看，但结论作废，且面试一问"两边输入是什么"就穿。

## 二、四臂设计（同一 query 集、同一 bge-m3、同一单元粒度）

| 臂 | 索引内容 | 回答的问题 |
|---|---|---|
| `A. raw-emb` | 原文按节内固定切块（≈500 字）直接嵌入 | 对照组：不做任何加工，稠密检索能到哪 |
| `B. qag-emb` | 原文切块 → LLM 生成 QA 对 → **只嵌问题**（每块 3 问）→ 命中回映射到节 | **传统 QAG 基线**（R1） |
| `C. struct-thin` | 标题 ＋ 章旨 ＋ 检索词 | 本项目方法·薄索引 |
| `D. struct-full` | 标题 ＋ 章旨 ＋ 检索词 ＋ 疏解 | 本项目方法·厚索引 |

可选追加（视首轮结果决定）：`qag-ema`（嵌问题＋答案）、`BM25` 对照、LLM 导航臂（真跑子代理）。

## 三、指标

- **Recall@k**（k=1/3/5）：gold 节是否出现在 top-k（同一节多个块命中只算一次）
- **MRR@5**：首个 gold 命中位置的倒数均值
- 分维度报告：按书（子平真诠／滴天髓／穷通宝鉴）、按问法（user 口语／analyst 分析师）
- 附记成本：各臂索引条目数、嵌入 token 数（可复算）

## 四、query 集

每节 × 两种风格 = 259×2 = 518 条：
- `user`：现代口语用户问法（禁古文词、禁章节名）
- `analyst`：分析师检索式（含日主/月令/结构条件，禁与标题逐字相同）

生成后过两道检查：① 自动扫描是否含标题/书名泄漏；② 人工抽检 + 检索失败案例复核 gold 合理性。

## 五、复现

```bash
cd 古籍/eval
python build_corpus.py        # → data/corpus.json（259 节）
python gen_queries.py         # → data/queries.jsonl（518 条，可断点续跑）
python build_qag_index.py     # → data/qag_index.jsonl（R1：只用原文层）
python run_eval.py            # → data/results.json + 打印指标表
```

嵌入缓存：`data/emb_cache.jsonl`（sha1 键，重跑不重复调 API）。API key：`~/.pi/agent/auth.json` 的 siliconflow。

## 结果速览（462 条有效题）

| 方案 | 单次检索 R@5 | 同款重排后 R@5 |
|---|---|---|
| 结构法（注解嵌入） | **77.5%** | **93.1%** |
| 原文切块直嵌（对照） | 78.8% | 92.2% |
| QAG（问题+答案） | 71.4% | 89.0% |
| QAG（标准） | 65.2% | 82.5% |
| 三派导航（无向量库） | — | **93.1%**（R@1 87.9%） |

结论：单次检索结构法优于 QAG（相对 +18.9%）；但重排后各臂趋同 → **结构化的收益不在召回，在引用分层、可校验、免向量库**。详见 `RESULTS.md`。
