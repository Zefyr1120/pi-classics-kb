# 古籍知识库检索评测 · 结果报告

> 评测日期：2026-09-19｜语料：《子平真诠》47 章 ＋《滴天髓》64 章 ＋《穷通宝鉴》148 节 ＝ 259 节
> 协议与红线见 `README.md`｜全部产物在 `data/`｜脚本在本目录

---

## 一、结论摘要

1. **同等单次检索条件下，结构化知识库优于 QAG**：R@5 77.5% vs 65.2%（相对 +18.9%）；R@1 48.7% vs 38.3%（相对 +27.2%）。
2. **QAG 是全场最弱的一种索引方式**：即使给它配同款 LLM 重排（top-20 候选），R@5 也只有 82.5%~89.0%，低于原文基线（92.2%）与结构法（93.1%）。**"生成问答对"这一步本身有损**——它的候选池上限只有 84.0%（qag-emb）/ 90.7%（qag-ema），而原文/结构法为 92.9%/93.5%。
3. **三派导航（不建向量库）达到与向量方案同等的召回**：R@5 93.1%、R@1 87.9%，索引就是 markdown 本身（无嵌入管线、无向量库）。
4. **重排器是主要增益来源**：不重排时索引表示之间差距明显（65.2%~78.8%）；加 LLM 重排后各臂趋同（82.5%~93.1%）——这是 IR 的已知现象（强 reranker 抹平表示差异）。**结论：结构化知识库的收益不在召回率，而在引用分层、可校验、免向量库。**

## 二、测试集怎么来的（462 条有效题）

| 步骤 | 数量 | 说明 |
|---|---|---|
| 语料节 | 259 | 三本书的分层重建单元 |
| ├ 占位节 | −7 | 原文仅为标题行（如"论丁火"），KB 自述"不构成可引用条文"→ 不入评测 |
| └ 可评测节 | 252 | 全部被测试集覆盖 |
| 生成 query | 518 | **每节 2 条**：`user`（现代口语用户问法）＋ `analyst`（分析师检索式） |
| 排除·占位节产出 | −14 | 7 节 × 2 风格 |
| 排除·零可答漂移题 | −42 | 判定器：生成出处被否 **且** 候选池内无一节可答 → 题面无效（IR 标准：无相关文档的 query 不计入 recall） |
| **有效 query** | **462** | user 212 ＋ analyst 250；覆盖全部 252 节 |

**防循环论证**（红线 R1–R4）：query 生成器只喂 `## 原文`（＋底本自带原注），**不见**标题／章旨／疏解／检索词；QAG 索引只进原文层，注解层一个字不入；gold 单文件、两臂共用。

**gold 校准**：初值＝query 的生成出处节（严格单 gold）。再用 **TREC pooling**：汇集全部参评系统 top-5 组成候选池（均长 ~19 节）→ LLM 逐题判定"能否直接作为回答依据"（只给原文，不给任何注解）→ gold 集 = {生成出处} ∪ {判定接受的节}。结果：238/518 条为多 gold，109 条生成出处在判定中被否——这两类都说明严格单 gold 会系统性低估所有臂。

## 四、失败与局限

- 主要失败集中在《穷通宝鉴》相邻月令条目（如"丁火生丑月" vs 十月／十一月丁火）与《滴天髓》抽象章（诗句短、题面与章节主题易漂移）。
- 重排臂只落了候选池与汇总指标，未逐题落盘（主结论即单次检索部分有逐题明细 `results_final2.json`）。
- 评测模型：测试集生成＝DeepSeek-V3.2；判定／重排＝deepseek-chat；嵌入＝bge-m3。导航臂用 LLM 导航，与 QAG 的稠密检索**不是同一种算力预算**（导航臂查询时要多花 LLM 调用）——这正是生产方案的取舍：**省的是索引构建与向量库，贵在查询**。
- 单一语料域（中文古籍命理），结论不宜外推；但评测协议（红线隔离＋池化 gold）可迁移。

## 附录：通俗版讲解（给不熟悉 RAG 的读者）

> 面试前看这一份就够了。全部用"找资料"打比方，不需要 RAG 背景。

### A1. 要测什么

把古籍库想成一个**图书馆**：252 个书架格子（每格是一节，如"正月乙木""论用神格局高低"）。
任务是：**给一个问题，能不能找到该看的那一格？**

- "乙木生在寅月，丙火和癸水怎么配合" → 应命中 `穷通宝鉴·正月乙木`
- 找到了＝命中；没找到＝漏。这就是 **Recall@k（召回率）**：标准答案是否出现在前 k 个结果里。

**为什么主看召回率**：系统是给分析师 agent 用的——它拿到候选节后会自己读、自己判断。致命的是"依据根本没被找出来"，而不是"排在第三位"。

### A2. 基线：传统 QAG 是什么

**QAG = Question-Answer Generation（问答对生成）**，RAG 圈的常见做法。一句话：**把"文章"改写成"可能被问到的问题"，检索时匹配问题、不匹配文章。**

| 步骤 | 做什么 | 本次参数 |
|---|---|---|
| ① 切块 | 古文切小段 | 节内 500 字、重叠 80 字 → 304 块 |
| ② 生成问答对 | LLM 读每块，编 3 个"用户可能问的问题"＋答案 | 304 × 3 = **912 个问答对** |
| ③ 建向量库 | 把问题（或问题+答案）转成向量 | bge-m3，1024 维 |
| ④ 检索 | 用户提问 → 向量 → 找最像的生成问题 → 定位原文 | 余弦相似度 |

**它的动机**：古文和现代问法差得远（"非丙不暖" vs "天冷我需要什么"），直接拿古文做索引匹配不上；改写成现代问题就"同一种话"了。

**它的代价（本次量化）**：第②步是**有损压缩**——LLM 只覆盖它理解到的部分，原文信息会丢、会漂移。证据：QAG 的候选池上限只有 **84.0%~90.7%**（有 10%~16% 的问题连正确答案的影子都召不回来），而原文直嵌 92.9%、结构法 93.5%。

### A3. 本项目的方法：结构化知识库 + 渐进式披露

不在"怎么匹配"上做文章，而是先把资料整理成"能顺着读下去"的结构：

| 层级 | 内容 | 作用 |
|---|---|---|
| 书级 `AGENTS.md` | 这本书多少章、每章讲什么、何时用 | 目录 |
| 干级/篇级索引 | 这一篇多少条、各覆盖哪个月令、何时调用 | 分目录 |
| 节的注解 | 章旨 ＋ 检索词 ＋ 疏解（判定链、易误读） | 摘要卡 |

检索时不做向量匹配：**LLM 读目录 → 缩小到某本书/某一干 → 选定条目**。索引就是 markdown 本身——**不建向量库、不要嵌入管线**。

### A4. 六个臂（把变量拆开，才能说清是哪一步起作用）

| 臂 | 索引用什么 | 回答什么问题 |
|---|---|---|
| `raw-emb` | 原文切块直接向量检索 | **不做任何加工**能到多少？（对照） |
| `struct-thin` | 标题＋章旨＋检索词 | 薄加工够不够？ |
| `struct-full` | 标题＋章旨＋检索词＋疏解 | 厚加工够不够？ |
| `qag-emb` | 生成的问题（标准 QAG） | QAG 基线 |
| `qag-ema` | 生成的问题＋答案 | 给 QAG 加料能否救回 |
| `nav-三派` | LLM 走导航索引（无向量库） | 生产方案 |

### A5. 测试集与防作弊

- **出题**：252 节 × 2 风格（口语用户问法 / 分析师检索式问法）= 518 条 → 筛出 **462 条有效**（剔除 7 个占位节与 42 条零可答题）。
- **防循环论证**：出题人只能看 `## 原文`，**看不到**章旨/疏解/检索词——否则等于拿答案出题，数字作废。
- **红线**：QAG 的库里只能进原文（＋底本自带原注）；注解层一个字都不许进，否则等于给对手塞答案。写成了代码断言 + 独立验证脚本（`verify_isolation.py`），可复现。
- **gold 校准（TREC 池化）**：所有参评系统的前 5 结果汇成候选池（均长 ~19）→ 另一模型逐条判定"能否直接回答"（只给原文）→ 标准答案 = 生成出处 ∪ 判定接受。结果：238 条被扩为多 gold，109 条生成出处在判定中被否。
- **踩过的坑（值得讲）**：第一版池化只汇集了向量臂的候选 → 导航臂找到的更优章节没进池、没被判定，全算成"错"，滴天髓的分数虚假掉到 17%。这就是**池化偏见**，必须让每个参评系统都进池。

### A6. 指标怎么读

| 指标 | 含义 | 本次（462 题） |
|---|---|---|
| R@1 | 第一名就命中 | 结构法 48.7% / QAG 38.3% |
| R@3 | 前三名内命中 | 70.3% / 57.6% |
| **R@5** | 前五名内命中（简历用） | **77.5% / 65.2%** |
| MRR | 命中位置的平均倒数 | 0.597 / 0.485 |
| 候选池上限 | 正确答案有没有被召回到池里（物理天花板） | 93.5% / 84.0% |

**单次检索 vs 重排后**：前者反映"索引本身好不好"（结构法 +18.9%）；后者反映"完整管线能到多少"（三派导航 93.1%）。
**重排（rerank）**：便宜方法粗筛 20 个候选，贵的模型（LLM）再精排——先让实习生抽 20 本书、专家再排序。这是 RAG 标配组件，所以**必须也给 QAG 配同款**，否则不公平。

### A7. 面试口播版（背这段）

> 我自建了一个检索评测来验证技术选型：252 节的古籍库、462 条标注问题；出题时只让模型看原文、看不到注解，防循环论证；标准答案用 TREC 池化加相关性判定校准。同样的单次检索条件下，结构化知识库 R@5 77.5%，传统 QAG（切块生成问答对再向量召回）65.2%，相对提升 18.9%。我还量化了 QAG 的短板——候选池上限只有 84%，说明问答对生成本身有损。最后生产方案的三派导航，不建向量库也做到 R@5 93.1%。不过我要如实说：加重排后各方案差距会收窄，所以结构化知识库真正的价值在引用分层和可校验，不在召回率。
